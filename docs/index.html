QuantSynthica Documentation

A unified quantitative financial engine combining yfinance, TradingView-Screener, and Screener.in with Modern Portfolio Theory, DCF valuation, algorithmic backtesting, and sentiment analysis.

📦 PyPI: quantsynthica 1.1.1
⚡ Execution: 100% Serverless & Zero-Cost
🌐 REST Endpoints: 53 APIs + WebSockets
📜 License: Apache-2.0

Overview & Architecture

Dual-mode architecture designed for both individual quants and institutional systems.

QuantSynthica operates seamlessly in two distinct deployment models:

  • Standalone Python Library (Zero-Server, Zero-Cost): Runs 100% locally in your Python script, Jupyter notebook, or Google Colab. Does not require any external backend server or API key. Perfect for algorithmic researchers and quants.
  • High-Throughput REST & WebSocket Microservice: FastAPI container with Redis distributed caching, PostgreSQL/SQLite persistence, rate limiting, and real-time tick streaming. Deployable on Docker, Render, Railway, or AWS.
ℹ️ REST API Base URL Notice:

https://your-deployment-url.com used in the cURL and WebSocket examples across this documentation is a placeholder. To use the REST endpoints, you must deploy your own instance (via Docker, Render, Railway, or AWS as documented under Installation), OR use the zero-server Python SDK (pip install quantsynthica) which runs directly in your process without requiring any backend server.

Authentication & Security

How API key security is configured, enforced, and passed.

QuantSynthica supports API key authentication via HTTP headers for hosted microservices. In zero-server Python SDK mode (import quantsynthica as qs), no authentication or server is required.

1. Header Format

When authentication is enabled, pass your secret key in the X-API-Key request header: 

curl -X GET "https://your-deployment-url.com/api/v1/market/RELIANCE/quote" \
  -H "X-API-Key: your_secret_api_key" \
  -H "Accept: application/json"
from quantsynthica import QuantSynthica

client = QuantSynthica(
    base_url="https://your-deployment-url.com",
    api_key="your_secret_api_key"
)
quote = client.market.get_quote("RELIANCE")

2. Key Generation & Configuration

When self-hosting via Docker or local server, configure your key in .env or environment variables:

Environment Variable Default Value Description
API_KEY "qs_live_dev_secret_key_12345" The valid secret key required to access protected endpoints.
API_KEY_REQUIRED false Set to true in production to strictly enforce API keys. By default, it is false (disabled for local development).

3. Authentication Status Codes

  • 401 Unauthorized: The X-API-Key header was missing when API_KEY_REQUIRED=true.
  • 403 Forbidden: The supplied X-API-Key does not match the configured API_KEY.

Errors & Rate Limits

SDK exception hierarchy, HTTP status codes, and server throttling thresholds.

SDK Exception Hierarchy

The Python client SDK provides strongly-typed exception classes derived from QuantSynthicaError:

Exception Class HTTP Status Raised When
AuthenticationError 401 / 403 API key is missing, invalid, or unauthorized.
NotFoundError 404 Ticker symbol, filing, or endpoint does not exist.
ValidationError 422 Request body or query parameters fail validation schema.
RateLimitError 429 Request velocity exceeds client rate limit or upstream throttle.
ServerInternalError 500 / 502 Microservice failure or upstream provider (Yahoo/TradingView/Screener) failure.
APIConnectionError Network Client cannot connect to the server (connection refused or timeout).
QuantSynthicaError Base Base exception class for all above SDK errors.

Server Rate Limit & Throttling Thresholds

The microservice includes rate-limiting and provider protection to prevent IP bans:

Component / Scope Threshold Mechanism
Global Client Rate Limit 100 req / minute Per-IP / client sliding window rate limiter (GLOBAL_RATE_LIMIT=100).
Screener.in Upstream Throttle 1.5s interval Minimum 1.5 seconds delay between consecutive corporate filings requests.
yfinance Upstream Throttle 0.5s interval Minimum 0.5 seconds delay between market data requests.
Redis Caching Layer 60s – 24h TTL Repeated requests within TTL are served from cache without upstream hits (Quotes: 60s, Quant: 15m, Fundamentals: 24h).

4-in-1 Institutional Valuation Models

Discounted Cash Flow, Piotroski 9-point score, Altman Z bankruptcy zones, and Graham Number.

PYTHON qs.get_valuation(symbol: str) -> DotDict
GET /api/v1/valuation/{symbol}

Runs four distinct fundamental mathematical valuation frameworks simultaneously:

  • DCF Model: Multi-year free cash flow projections, WACC discount hurdle, terminal growth, equity bridge.
  • Piotroski F-Score: 9-point accounting health criteria across Profitability, Leverage/Liquidity, and Operating Efficiency.
  • Altman Z-Score: Multivariate discriminant bankruptcy prediction (Safe Zone, Grey Zone, Distress Zone).
  • Graham Number: Conservative value investing upper bound based on EPS and Book Value.
import quantsynthica as qs

print(f"Graham Number:      ₹{val.graham.graham_number} (Safety: {val.graham.margin_of_safety_pct}%)")

Real-Time WebSockets Tick Streaming

Ultra low-latency bidirectional market data quote streaming.

WEBSOCKET wss://your-deployment-url.com/api/v1/ws/quotes

Connect via any standard WebSocket client to stream tick quotes.

import asyncio
import websockets
import json

async def stream():
    uri = "wss://your-deployment-url.com/api/v1/ws/quotes"
    async with websockets.connect(uri) as ws:
        # Subscribe to symbols
        await ws.send(json.dumps({
            "action": "subscribe",
            "symbols": ["RELIANCE", "TCS", "AAPL"]
        }))
        while True:
            tick = await ws.recv()
            print("Tick:", tick)

asyncio.run(stream())
const ws = new WebSocket("wss://your-deployment-url.com/api/v1/ws/quotes");

ws.onopen = () => {
  ws.send(JSON.stringify({
    action: "subscribe",
    symbols: ["RELIANCE", "TCS", "AAPL"]
  }));
};

ws.onmessage = (event) => {
  console.log("Tick update:", JSON.parse(event.data));
};
